# Teachers Manager — نسخة v31 (نوفمبر 2026)

الملف ده مش بيتنشر على الموقع (`.assetsignore`). كل ملفات الشرح القديمة اتشالت، وده الملف الوحيد.

## التركيب بالترتيب

### 1) قاعدة البيانات
شغّل الملفين في Supabase ← SQL Editor (الترتيب مش مهم، والاتنين آمنين لو اتشغّلوا تاني):
- `DB_v30.sql`: جدول تسجيل أخطاء n8n.
- `DB_v31.sql`: عدّاد المزامنة اللحظية + أعمدة الطالب التجريبي.

بعد `DB_v31.sql` اتأكدي إن Realtime مفعّل: Supabase ← Database ← Publications ← `supabase_realtime`، ولازم يكون فيه جدول `tm_sync`. الملف بيضيفه لوحده.

### 1.5) n8n — ملفات الطالب التجريبي (v31)
استوردي الـ 5 ملفات اللي في `n8n/v31-import/`، كل واحد مكان الـ workflow اللي بنفس الاسم، وبعدين Save وPublish:
`QTM_ Create Student` و`update-student-info` و`get_students` و`get-today-lessons` و`get_schedules`.
الملفات دي فيها كمان إصلاحات v30. ونفس النسخ موجودة في `n8n/patched/`.

### 2) n8n — إصلاح كل الـ workflows مرة واحدة (من غير ما تفتحهم واحد واحد)
1. Settings ← n8n API ← Create an API key، وانسخ المفتاح.
2. Import from File ← `n8n/TM-Maintenance-Patch-All-v30.json`.
3. افتح عقدة **Patch All Workflows** والصق المفتاح في أول سطر (`N8N_API_KEY`).
4. **أول تشغيل** (DRY_RUN = true): Execute Workflow ← اقرا التقرير (مفيش حاجة بتتغيّر).
5. خلّي `DRY_RUN = false` وشغّل تاني. نسخة احتياطية من كل workflow قبل التعديل بتطلع ملف تنزّله من الـ Output.
6. لو أي workflow كتب "افتح الـ workflow ودوس Publish": افتحه ودوس Publish/Active.
7. امسح مفتاح الـ API من العقدة بعد ما تخلص (أو امسح الـ workflow كله).

الملف بيعمل إيه في الـ workflows الموجودة عندك فعلًا (النسخ الأحدث، مش نسخ قديمة):
- **المصادقة:** بدل `throw new Error('Unauthorized')` بيرجّع 401/503 مفهومة. الموقع بيجدّد الجلسة ويعيد الطلب لوحده. وفيه كاش 15 دقيقة وإعادة محاولة لو Supabase اتأخر.
- **Postgres:** إعادة المحاولة 3 مرات (عشان خطأ DNS والانقطاع اللحظي).
- **الإشعارات المجدولة:** التوقيت بقى `Africa/Cairo`. قبل كده كانت بتمشي على توقيت السيرفر.
- **create-schedule / update-schedule:** الحصة بتتحفظ في ميعاد متعارض لما المدرس يوافق (`allow_conflict`).
- **فحص:** بيطلّعلك اسم الـ workflow والعقدة اللي فيها `require('fs')` (سبب خطأ `Module 'fs' is disallowed`).
- مابيلمسش workflows المشاريع التانية اللي على نفس n8n (إلا لو `SCOPE_ALL = true`، وساعتها بيضيف إعادة المحاولة والتوقيت بس).

**طريقة بديلة (يدوي):** مجلد `n8n/patched/` فيه الـ 58 workflow بتوعك (من التصدير الأخير بتاريخ 5 نوفمبر) بعد الإصلاح. افتحي كل workflow ← ⋯ ← Import from File ← اختاري الملف بنفس الاسم ← Save ← Publish. ملف TM Maintenance أسرع وأأمن لأنه بيعدّل اللي على السيرفر مباشرة.

**workflows الموقع بيطلبها ومش موجودة في التصدير:** `list-books` (قايمة "مكتبتي" وكتب الحصة)، `track-events`، `update-profile`.
- لو مكتبتي شغالة عندك يبقى `list-books` موجود بس ماتصدّرش، فسيبيه زي ما هو.
- لو مش موجود: استوردي `n8n/list-books-v30-IF-MISSING.json` واختاري بيانات Postgres وفعّليه. ماتستورديهوش لو موجود، عشان رابطين بنفس الاسم بيتعارضوا.

### 3) n8n — Error Workflow جديد (اختياري، وننصح بيه)
Import ← `n8n/TM-Error-Logger-v30.json` ← اختار بيانات Postgres. بعدها حط رقمه في `NEW_ERROR_WORKFLOW_ID` في ملف الإصلاح وشغّله تاني. كل الأخطاء بتتسجل في `teachers_manager.n8n_errors`، والخطأ المكرر بيتسجل مرة واحدة كل 10 دقايق.

### 4) خطأ DNS في Postgres (على سيرفر Contabo)
- في بيانات **Postgres** في n8n استخدم **Session Pooler** بتاع Supabase بدل `db.<ref>.supabase.co` (الأخير IPv6 بس، وسيرفرات كتير مابتدعمهوش):
  - Supabase ← Project Settings ← Database ← Connection string ← **Session pooler**
  - Host: `aws-0-<region>.pooler.supabase.com`، Port: `5432`، User: `postgres.qdpnupgqvjxlrmwwgmij`، SSL: require
- في `docker-compose.yml` تحت خدمة n8n (وخدمة runners لو موجودة):
  ```yaml
  dns:
    - 1.1.1.1
    - 8.8.8.8
  ```
  وبعدها `docker compose up -d`.

### 5) خطأ `Module 'fs' is disallowed`
n8n الجديد (Task Runners) بيمنع `require('fs')` في عقدة Code. مفيش ولا workflow من الـ 58 بيستخدم `fs`. والـ Error Workflow اللي كلهم مربوطين بيه (`en9U7V1q0b2InEH8psjCL`) مش موجود في التصدير، فغالبًا هو السبب: بيشتغل مع كل خطأ، فبيتكرر مع كل Unauthorized. الحل الأسرع: استوردي TM Error Logger وحطّي رقمه في `NEW_ERROR_WORKFLOW_ID`. ملف الإصلاح كمان بيفحص كل الـ workflows على السيرفر (حتى اللي مش في التصدير) وبيقولك فين `fs` بالظبط. الحل في العقدة دي:
- قراءة/كتابة ملفات ← عقدة **Read/Write Files from Disk** بدل الكود.
- بيانات binary ← `this.helpers.prepareBinaryData(...)` و `this.helpers.getBinaryDataBuffer(...)`.
- لو لازم fs فعلًا: `NODE_FUNCTION_ALLOW_BUILTIN=fs` على حاوية n8n وحاوية الـ runners (مش مستحسن).

### 6) الموقع
ارفع محتوى المجلد ده كله مكان القديم على GitHub. رقم النسخة بقى `?v=39`. الصفحات المفتوحة بيظهر فيها "فيه تحديث جديد ← حدّث".

## الجديد في v31
- **مزامنة لحظية مضمونة:** عدّاد صغير في قاعدة البيانات بيزيد لوحده مع أي تغيير، مهما كان مصدره (لابتوب، موبايل، n8n).
  - الأجهزة المفتوحة بتعرف بالتغيير خلال ثانية عن طريق Supabase Realtime.
  - الموبايل لما يرجع من الخلفية بيسأل "فيه تغيير؟" بطلب صغير جدًا لـ Supabase، مش لـ n8n.
  - لو Realtime واقع، فيه فحص كل 20 ثانية.
- **الكاش مختوم برقم العدّاد:** طول ما مفيش تغيير، التنقل بين الصفحات بيبقى من الجهاز فورًا (لحد 10 دقايق). وأول ما فيه تغيير، الكاش بيتمسح.
- **الطالب التجريبي:**
  - "🎯 حصة تجريبية" من صفحة الطلاب: الاسم وميعاد الحصة التجريبية (مرة واحدة).
  - بعد الحصة يظهر كارت "قرّر" في الرئيسية وصفحة الطلاب وملف الطالب، وبعد حفظ الحصة.
  - "ضيفه لطلابي": مواعيده الأسبوعية، ونظام الدفع (باقة أو كل كام حصة)، والحصة التجريبية تتحسب من الباقة أو تبقى مجانية.
  - "مكملش": حذف الطالب. "غيّر الميعاد": لو التجربة اتأجلت.

## الجديد في v30
- **الجلسة:** بتتجدد بالوقت الحقيقي حتى لو ساعة الموبايل غلط (التوقيت الصيفي). ولو السيرفر رد 401: تجديد وإعادة الطلب، من غير ما المدرس يخرج.
- **السرعة:** نفس طلب القراءة بيتبعت مرة واحدة بس، وفيه كاش 40 ثانية بين الصفحات بيتمسح مع أي حفظ. ورابط ملف الكتاب بيتحفظ، والكاش القديم على الموبايل بيتنضف.
- **المزامنة اللحظية بين الأجهزة:** Supabase Realtime Broadcast. لو القناة مش متاحة، بيرجع للتحديث كل دقيقتين.
- **الإشعارات:** طلب الإذن بيحصل جوه ضغطة المدرس نفسها (الآيفون كان بيرفض الطلب لو اتأخر)، والاشتراك الواقع بيتصلّح لوحده.
- **تقرير ولي الأمر:** فيه رقم الحصة والتاريخ كامل. وتقرير الشهر فيه كل حصة برقمها وتاريخها، وفيه زرار "تقرير لولي الأمر" لأي حصة قديمة في ملف الطالب.
- **حصتين في نفس الميعاد:** تحذير واضح قبل الحفظ، وفي الجدول والرئيسية الحصص المتعارضة ليها شكل مختلف (إطار متقطع أحمر + ⚠️ + "في نفس الوقت مع…") وتنبيه بعددها.
- **المجموعات:**
  - تاب "التقارير": تقرير المجموعة الشهري لجروب واتساب، وتقرير الشهر لكل طالب، وتقارير آخر حصة.
  - في الحصة: كتب الحصة (والرسم عليها بيتحفظ للمجموعة) مع "سجّل الصفحة في الحصة"، والحصص اللي فاتت، ورابط الحصة، والنافذة الصغيرة فوق Zoom/Meet، و"تقارير أولياء الأمور" لأي حصة متسجلة برقم حصة المجموعة وتاريخها.
